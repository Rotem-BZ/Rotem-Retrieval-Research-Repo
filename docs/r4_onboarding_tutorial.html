01 / 07

Configure one project, not a global environment.

R4 is a monorepo, but each research project owns its Python requirements and lockfile. We will use projects/query-repetition as the working environment for the whole tutorial.

System tool

Git

Clones the repository and records the exact code state in run manifests.

Environment tool

uv

Resolves Python, installs the locked project, and executes tools inside its environment.

Managed for you

Python ≥ 3.11

uv sync can provision the required interpreter. No manual virtual-environment activation is needed.

Preflight

PowerShell · any directory
PS> git --version
PS> uv --version
Bash · any directory

$ uv --version

Build Hydra commands interactively.

Do not begin by memorizing long override strings. The repository’s command builder discovers valid choices in context, validates the final composition, and gives you a copyable uv run stage … command.

>_

Recommended starting point

interactive_build_command.py

The helper uses the nearest configs/ directory at or above your current working directory. In this tutorial that means project choices first, then shared retrieval-core fallbacks.

It knows configuration

Project choices are included

Because you launch it inside projects/query-repetition, the builder can offer query_repetition/dense_query_repetition alongside shared core pipelines.

It knows artifacts

Only completed dependencies appear

Inference can select an existing index or input mapping. Evaluation can select completed inference runs for the chosen dataset.

It exposes advanced control

Review or edit selected configs

Answer y at the review prompt to switch a nested choice or edit fields such as top_k, concurrency, or stage.run_id.

It fails early

The final config is composed first

Missing required values, invalid combinations, and unavailable dependencies are reported before the command is handed back.

The helper removes guesswork, but the command remains an explicit research record. Learn its five parts so you can review, adjust, and commit it confidently.

REFERENCE

Troubleshoot by symptom.

Most onboarding failures come from the working directory, missing upstream artifacts, immutable IDs, or first-run downloads.

The builder does not show the query-repetition pipeline

Run it from projects/query-repetition. The helper selects the nearest config tree; from the repository root it cannot infer that you intended this project. Alternatively, pass --config-dir projects/query-repetition/configs with the project environment selected explicitly.

Inference says no completed indexes were found

Run the indexing stage first. The builder deliberately lists only completed indexes under the project’s configured artifacts/indexes directory.

Evaluation says no completed inference runs were found

Complete inference for the selected dataset first. Evaluation will not guess “latest” and will not offer incomplete or other-dataset runs.

An index or run ID already exists

Artifacts are immutable. Accept the builder’s next available index suffix or choose a new run ID. Do not overwrite or silently reuse a folder from a different execution.

The first model-backed stage appears slow

E5-small weights may be downloading and initializing. Subsequent runs normally reuse the local cache. Check run.log and network access before assuming the pipeline is hung.

build-command is not recognized

The short command is a Bash alias defined in bash_aliases.sh. Source that file in Bash, or invoke uv run python ../../awesome-dev-tools/interactive_build_command.py directly from the project on any supported shell.

The command was printed but not copied

Clipboard failure is non-fatal. Copy the printed command manually. Linux desktop sessions may need xclip or xsel.

Git reports “dubious ownership”

Add only this trusted checkout’s absolute path to Git’s safe.directory list using the quick-start command in the setup section.
